Auslan Fingerspelling Web App

Capstone project turned passion build with Victor Goh . I focused on the fingerspelling feature: training pipeline, architecture choices, and on-device inference that runs entirely in the browser.

Why

We wanted a lightweight, gamified way to practice fingerspelling to enhance accessibility to Auslan. Without server costs or privacy tradeoffs. The app had to run fully on-device.

What

A browser-based Auslan fingerspelling recognizer that uses MediaPipe for real-time hand landmarks and a custom TensorFlow model for letter classification. Static deployment, no backend.

Design Decisions

  • Image-based CNN inference was too heavy and costly for a static site.
  • MediaPipe Hand Landmarker provides a compact, real-time abstraction - 21 3D landmarks (63 values) instead of processing raw pixel data.
  • Landmark tensors enabled small MLPs instead of heavy CNN/RNN models, keeping inference lightweight for browser deployment.
  • No server-side processing means zero latency, complete privacy, and no ongoing hosting costs.

In our first iteration, we trained heavier CNNs (including EfficientNet variants) and reached around 90% accuracy on the training and validation splits. However, real-world testing performed poorly because the dataset was not varied enough in background, lighting, and pose angles. The compute cost also implied provisioning a server to host the model on AWS (e.g., SageMaker), which conflicted with a lightweight, static web app.

We iterated with a different approach: a two-part system with MediaPipe landmarks plus a compact classifier. That reached slightly higher training accuracy (around 92%) and, more importantly, generalized much better in real-world webcam inference.

Training Flow

  1. Collect raw images for 26 classes (A-Z) with diverse hand positions, lighting conditions, and backgrounds.
  2. Run MediaPipe Hand Landmarker on each frame to extract hand skeleton.
  3. Extract worldLandmarks (3D coordinates in real-world space), reshape to [21,3,2] for two hands.
  4. Pad missing hand landmarks with [-1,-1,-1] to handle one-handed signs.
  5. Train lightweight classifiers with validation split, learning rate scheduling, and early stopping.
  6. Export best model to TensorFlow.js for in-browser inference with quantization for smaller model size.

Architecture Exploration

The key challenge was building an accurate classifier that could run in real-time in the browser. Working with MediaPipe's 21-landmark output (63-dimensional tensor for 3D coordinates), I experimented with several architectures:

Simple 3-Layer MLP

Basic fully-connected network as a strong baseline. Fast inference but limited capacity to learn complex hand configurations.

Bilateral MLP

Processes left and right hands in separate branches before fusion. Better at learning hand-specific features and handling asymmetric signs.

Bilateral MLP with Residual Connections

Added skip connections to improve gradient flow. Best accuracy without significant latency increase - this became the final architecture.

Lightweight CNN (Experimental)

Tested but not ideal - CNNs excel at spatial locality in grid-structured data (images), but our input is a flat coordinate vector where landmarks don't have inherent 2D adjacency.

Technical Challenges

  • Hand orientation normalization: Needed to handle different camera angles and user distances while maintaining accuracy.
  • Missing landmark handling: Some frames don't detect both hands - padding strategy was critical for model stability.
  • Real-time performance: Inference had to run at 30+ FPS on consumer hardware without GPU acceleration.
  • Model size constraints: TensorFlow.js models needed to be small enough for fast loading over web connections.
  • Class imbalance: Some letters are harder to capture than others, requiring careful data collection and augmentation.

Results & Learnings

The bilateral MLP with residual connections achieved strong accuracy on held-out test data while maintaining real-time performance in the browser. Key learnings included the importance of data quality over quantity, the effectiveness of hand-specific feature processing, and that simpler architectures often outperform complex ones for deployment-constrained environments.

Future improvements could include temporal smoothing across frames to reduce jitter, support for dynamic signs beyond fingerspelling, and transfer learning to handle different lighting conditions more robustly.
